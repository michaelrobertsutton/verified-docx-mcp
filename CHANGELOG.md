# Changelog

## Unreleased

- Cheaper write inputs (#113 part B):
  - `replace_range_markdown`, `replace_body_markdown`, `append_markdown`, `replace_cell_markdown` and `insert_table` take `markdown_file` (a `.md`/`.txt` path under the allowed roots, UTF-8, at most 2 MB) instead of inline markdown. The response reports `markdown_sha256` and `markdown_chars`; a path outside the roots is `DOCX_PATH_ESCAPE`. Approved runs read the file once at prepare, so the digest binds its content.
  - New `add_anchored_comment_batch`: 1-50 comments in one call, file mode all-or-nothing with one save, live mode stop-at-first-failure with per-item status. One audit record per call.
  - On the issue's session (10 paragraph rewrites, 12 comments) argument tokens fall 49% in live mode and 37% in file mode; see `docs/acceptance/113-write-inputs.md`.
- Cheaper write inputs (#113 part A): an anchored find, `"<prefix>…<suffix>"` with `expected_length` and/or `find_sha256`, names a long span without retyping it, in `replace_text`, `replace_text_batch`, `format_text`, `apply_style`, `delete_paragraph` and approved-run `replace_text` (no 230-character limit there once resolved). `replace_text` and its batch also take `para_ref` + `expected_sha256` for a whole paragraph. New errors `AMBIGUOUS_SPAN` and `PARA_HASH_MISMATCH`. Spans over 230 UTF-16 units need pane v68b (`anchored_find_v1`). A literal `…` stays plain text unless `expected_length`/`find_sha256` is passed. Paragraph hashes are computed by the caller (`locate.span_sha256`) until a read returns them.
- Section content digests (#117): `find_sections(digests=true)` adds `content_sha12` per heading section and `preamble_content_sha12`, covering text, tracked deletions, table structure (merged and nested cells) and anchored comment threads (author, text, resolved, replies). `live_revision` and `live_list_sections` take `content_digests=true` (one `body_ooxml` export; adds `content_sections` and `preamble_content_sha12`). Computed server-side only, from OOXML, so no pane change; `sha12` and section locks are unchanged.
- Trimmed read payloads (#111):
  - `list_open_items` gains `fields="summary"` (columnar, ~577 tokens for 27 comments; rows under `comment_rows`/`suggestion_rows`, never a `comments` key, `path` kept; scoped results carry `scoped: true`), `section_key`/`within_text` scoping and `include_correlation`. Its default `full` shape drops constant or derivable fields (`modified_time`, `scope`, live `w_id`/`quoted_text`, `reply_count`, empty `replies`, null top-level keys) and is 39.9% smaller on the 27-comment fixture.
  - `list_tables` reports `header_row` and `anchor_section_key`.
  - `list_styles` gains `type`/`name_contains` filters; `STYLE_NOT_FOUND` lists near matches instead of every style.
  - `live_status(path, verbose)` and `lock_status(verbose)` are compact by default (`live_status` still shows `locks` and this client's `client_id`; `lock_status` keeps `recent` and `ledger`). `STYLE_NOT_FOUND` adds `available_sample` when nothing is close.
  - A lean read envelope drops echoed paths, empty lists and `revision_detail` (`read_document(verbose=true)` restores it).
  - Read tools carry `readOnlyHint`/`idempotentHint`; destructive tools carry `destructiveHint`.
  - Fix: `resolve_comment`/`reply_to_comment` accept the `live:<epoch>:<id>` handles `list_open_items` returns.
- Cell edits keep their formatting (#107; checked on Word for Mac 16.114.3, results in `docs/acceptance/107-cell-editing.md`). `replace_cell_markdown` inherits the cell's first-run font name, size and colour (`inherit_format="none"` opts out; a live write on a pane without `cell_font_inheritance_v1` is refused rather than resetting the font; a link keeps its own colour). `delete_paragraph` may remove a non-final paragraph inside a cell (Word cannot remove a cell's final one: refused before writing). New `merge_paragraph_with_next` joins two paragraphs of one cell keeping both paragraphs' runs and hyperlinks (tracked merges refused; live mode refuses a pair whose paragraph properties differ, because Word keeps the second's; file mode keeps the first's). `insert_paragraphs` accepts `{"after_table_id": N}` and `{"empty_paragraph_after_table_id": N}`. `replace_text_batch` honours `within_row_containing` per edit. `live_save` no longer fails `LIVE_STALE` while someone types: it needs no body baseline and does not acknowledge a read, but still honours the lease and section locks. Pane capabilities `cell_font_inheritance_v1`, `cell_paragraph_merge_v1`, `paragraph_positions_v1`.
- New read-only `diff_table_vs_markdown` (#109): reports only the cells that differ between one Word table (`table_id`) or every table under a heading (`section_key`) and a markdown pipe table, as `{row, col, docx_text, md_text}`. Cell text is compared structurally (quotes, dashes, NBSP and whitespace folded; emphasis ignored unless `strip_emphasis=false`; escaped pipes, links and inline code handled). Merged-cell/nested tables and cells with fields, drawings or text boxes are listed under `unsupported`, and ambiguous selectors are refused: nothing missing or ambiguous is ever reported as equal. Works on file or live (`source`).
- Add guarded file/live `insert_table_row` and `delete_table_row` with 1-based positions, template formatting and expected-text deletion checks. Add `insert_table(like_table_id=...)` for direct-formatting copies with explicit overrides (pane v67). Live after-table copies insert a separator paragraph to preserve distinct tables. See `docs/acceptance/106-table-structure.md` for native acceptance and bounded template support.
- Bounded write evidence (#112): `append_markdown`, `replace_body_markdown`, `replace_range_markdown` and file-mode accept/reject return hashes, sizes and a 200-character excerpt instead of the whole before/after (`append_markdown` of one paragraph to a 20K-word document: ~98K to ~175 tokens). The full text stays in the audit log under `evidence_ref`; new `read_audit_evidence` fetches it. `verbose` never restores it.
- Live `delete_paragraph` returns counts and the two neighbouring paragraphs (pane v66, `compact_evidence_v1`). `format_text`/`apply_style` report `text_unchanged`, one excerpt and a `format_delta`; `runs_before`/`runs_after` need `verbose=true`.
- Compact `replace_text_batch` and approved-run reports (no echo of `run_id`/`manifest_sha256`, `performance` behind `verbose`, `section_diff` cut to 600 characters, `remaining_ranges` beside `remaining`); `live_changes_prepare` previews each operation's text. A lean envelope drops constants (`verified_via`, `document_name`, `audit_logged: true`, ...). Errors list at most five match contexts with `total_matches`, drop `ladder_report` unless `verbose`, use 12-hex stale hashes and omit `retryable` when false.

- `diff_body_vs_file` is normalized (quotes, dashes, NBSP, soft hyphens, NFC, trailing whitespace), returns hunks or a unified diff but never both, drops the text of equal hunks, and can be scoped by `section_key` and capped by `max_hunks`. `identical_raw` keeps the byte comparison. On the ~20K-word fixture an identical-document diff falls from ~99K to ~100 tokens.
- `read_document` gains inclusive `start_para_ref`/`end_para_ref` ranges (any format, file or live) and `to_file`, which writes the body to an allowed path and returns a summary with the file's sha256. `find_sections` entries carry `chars`; `find_sections(digests=true)` adds a per-section `sha12`.
- New `live_revision` tool returns the live revision and per-section digests in one pane round trip (pane op `body_hash`, capability `body_hash_v1`; pane v65). Older panes fall back to `body_ooxml`. `live_list_sections(compact=true)` returns `[key, heading, sha12]` rows.
- File-mode `list_open_items` now threads comment replies via `w15:paraIdParent`: replies are no longer listed as top-level comments, and each root reports a real `reply_count` and `replies` (`{id, author, date, text}`). The root comment's resolved state governs the thread. Shared threading walk lives in `projection.comment_thread_links`.

## 0.1.2 — 2026-10-16

- Batch approved cell preflight reads and use direct cell access, retaining fresh mutation-boundary checks and one-attempt independent verification.
- Negotiate transport-only heartbeats, queue idle hash samples separately, expose sample age/state, and reconnect expired panes without replaying unknown writes.
- Separate hash work from native operation sync metrics and use monotonic phase timers.

- Add explicit approved font/link segments for mixed inline replacements, independent formatting and unchanged-text verification.
- Allow text-only edits beside callout anchors while preserving complete shape definitions and refusing structural edits. Keep independent targets eligible after a proven prewrite deletion refusal.
- Add a capability-gated sequential cell stream with fresh scoped OOXML checks, one write attempt, independent per-target readback and durable per-operation acknowledgments.
- Record native sync counts, phase timings and bridge request counts in local execution evidence. Older panes and unsupported stream structures retain the conservative path after proven prewrite capability refusal.

## 0.1.1 — 2026-10-16

- Add digest-bound prepare/execute/resume for scoped live change sets, durable journals and explicit unknown-outcome reconciliation.
- Permit unrelated coauthor edits while preserving protected-section and target checks at the pane boundary.
- Attempt independent edits before retrying pre-write refusals; quarantine uncertain targets, save after all mutations, and resume final verification without replay.
- Include tables between adjacent top-level headings in protected section ranges; give scoped writes and readbacks a consistent verification deadline while retaining explicit timeout overrides.
- Keep full execution evidence local; return compact run reports.
